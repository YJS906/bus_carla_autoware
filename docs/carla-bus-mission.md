# Town05 수요 기반 정류장 정차 버스 미션

2026-10-22 미션 설계, 2026-10-26 진행 상태 정리. 전체 코스 근거는 2026-10-24,
단일 정류장 하차벨 근거는 2026-10-26 검증 기록이다. 이 문서는 요구사항과 진행 단계를 함께 관리하며, 아래의 서비스
동작·UI 요구사항은 구현 완료를 뜻하지 않는다.

빈 도로와 교통 차량 16대 조건에서 S01→S10→S01 노선 경유·복귀·목표 정지를
확인했다. 최종 교통 시험은 **2,005.33m 완주, 양쪽 충돌 센서 0건**이며 차량 16대를
끝까지 유지했다. GT 객체·신호 입력과 NPC 추종 보완을 사용한 서비스 정차 없는
한 바퀴 시험이다. 일시적 긴급 상태 2회와 순간 계획 경계 밖 차체 표본 5개가 남았다.
[최종 검증 기록의 final_traffic_lap](validation/carla-bus-lap-20261024/following-validation.json)과
[실행·검증 안내](carla-bus-operations.md)를 따른다.

**단계 0·1 완료, 단계 2~4 부분 완료, 단계 5·6 미완료**다.
2026-10-26에는 [S10 하차벨 시범 구간](carla-bus-service.md)을 추가해 바깥 차로 정차,
실제 정지 후 5초 대기, 요청 해제·재출발과 무요청 통과를 확인했다.
모든 정류장으로의 확장, 늦은 입력의 다음 정류장 이월, 승객 판단 및 버스 보행자 대응은
구현·검증이 남아 있다. 전체 코스 경유 성공과 서비스 정차 성공은 별도로 보고한다.

## 목표와 기존 결과

CARLA Town05의 고정 순환 노선을 Autoware + ROS 2로 주행하면서, 하차 요청과
정류장 대기 승객에 따라 정차 여부를 결정한다. 발표 주제는
**“승하차 수요에 따른 자율주행 버스의 정류장 접근·정차·재출발”**로 잡는다.

기존 차량 회피·보행자 정지, Town05 지도·신호 연동을 기반으로 사용한다.
이전 성공은 GT 객체 입력의 특정 조건 시험이며, 센서 인식과 정상 배속 장시간
안정성이 완성된 것은 아니다. 상세 근거는
[행동 검증](carla-behavior-repair-20260922.md)과
[최종 회피 수정](carla-lane-start-fix-20260923.md)을 따른다.

기존 기준점은 `7d65001`, 보존 태그는
`backup/pre-bus-mission-20261022-151442`, 새 브랜치는 `mission/town05-bus`다.
전체 작업 폴더, Town05 외부 지도, GUI/교통 상태, Git bundle, CARLA/VTD 이미지는
`/home/a/autoware-task-backups/pre-bus-mission-20261022-151442/`에 보관한다.
복원 방법과 실제 백업 범위는 해당 폴더의 `RESTORE.md`, `manifest.json`을 따른다.

## 사용자가 정한 동작

| 하차벨 | 해당 정류장 대기 승객 | 버스 동작 |
|---|---|---|
| 눌림 | 없음 | 정류장 쪽 바깥 차로 접근 → 정차 → 재출발 |
| 안 눌림 | 있음 | 정류장 쪽 바깥 차로 접근 → 정차 → 재출발 |
| 눌림 | 있음 | 한 번 정차하여 두 요청 처리 → 재출발 |
| 안 눌림 | 없음 | 정류장 쪽 바깥 차로 접근 → 서비스 정차 없이 통과 |

마지막 경우에도 신호·장애물·보행자 때문에 필요한 정지는 유지한다.
정류장 서비스 정지와 교통 상황에 따른 정지는 UI와 평가 기록에서 구분한다.

“가까운 정류장”은 직선거리 최솟값이 아니라 **고정 노선의 진행 방향으로 다음에
도달하는 정류장**으로 해석한다. 반대편 정류장이나 이미 지나간 정류장은 제외한다.
순환 경계에서는 다음 바퀴의 첫 정류장으로 연결한다.

## 현재 운행 설정과 서비스 제안값

- 하차벨: 별도 데스크톱 UI가 포커스를 가진 상태에서 Space, 화면 버튼도 제공한다.
  S10 시범 구간에 구현했으며 요청 접수 후 버튼이 빨간색으로 깜빡인다.
- 정차 시간: S10 시범 구간에서 실제 정지 확인 뒤 시뮬레이션 시간 5초로 구현했다.
- 승객 판단 제안: GT의 보행자 위치를 정류장 대기 영역과 대조. 무작위로 근처를 지나는
  보행자와 구분하도록 지정 영역 안의 체류 여부를 사용한다. 영역·체류 기준은 검증 후 확정.
- 노선: 사용자 지정에 따라 **도심 → 서부 순환로 → 도심**, 정류장은 도심에 **10개**.
  생성한 노선과 정류장은 [노선 파일 안내](../scenarios/bus/README.md)를 따른다.
  현재 참조 노선은 약 2.03km이며 도심 정류장 간격은 약 56~168m,
  순환로를 거치는 S05→S06 구간은 약 1.18km다. 실제 주행 거리는 생성된 궤적에 따라 다르다.
- 현재 속도 상한: **도심 30km/h / 서부 순환로 50km/h**. 순환로 차선 변경 구간은
  20km/h 상한을 적용하고 신호·곡률·계획 결과에 따라 감속한다. 초기 10/20km/h
  시험 조건과 구분한다. 기본 제어 검증 도구의 기본값은 여전히 20km/h다.
- 배경 교통: NPC 추종 보완을 적용한 16대 노선 완주를 검증했다. 서비스 정차와
  승객 조건은 최소 교통 조건에서 먼저 검증하고 이후 통합한다.

사용자는 별도 정차 공간이 필요 없고 도로 위에 멈춰도 된다고 명시했다.
따라서 정차 공간·버스베이를 만들지 않고 **바깥 주행 차로 중앙에 정차**한다.
정류장은 횡단보도·교차로 내부를 피하여 도심에 골고루 배치한다.
완전한 등간격보다 도심 분포와 차로 연결을 우선한다.

## 입력과 상태 전이

상태는 `노선 주행 → 정류장 접근 → 정차 또는 통과 → 다음 정류장`으로 구성한다.
정차 분기는 `감속 → 정지 확인 → 승하차 대기 → 출발 가능 확인 → 재출발`을 거친다.

- 하차벨 요청은 한 번 누르면 유지한다. 키 반복 입력은 추가 요청으로 누적하지 않는다.
- 정류장 정차를 결정한 뒤 승객이 영역을 잠깐 벗어나도 정차 결정을 취소하지 않는다.
- 요청은 해당 정류장의 서비스 완료 뒤 해제한다. 신호 정지나 단순 저속 주행으로
  요청을 소비하지 않는다.
- 너무 늦은 하차벨 입력은 제동 여유에 따른 정책이 필요하다. S10 시범 버전에서는
  접수 마감 후 입력을 UI와 로그에 명시적으로 거부하며 자동 이월하지 않는다. 안전하게 정차할 수
  없는 경우 다음 정류장으로 넘기고 UI에 알리는 방안을 제안한다. 이는 구현 전에
  확정해야 할 예외 정책이며 사용자가 정한 기본 동작과 구분한다.
- 정차 중 새 하차벨은 현재 정류장에서 처리하는 것을 제안한다. 출발 이후 입력은
  다음 정류장 요청이다. 정확한 전환 시점은 상태로 관리한다.
- 대기 승객은 서비스 뒤 탑승 처리 상태를 가져야 한다. 같은 사람이 남아 있다는
  이유로 매 순환마다 다시 정차하지 않도록 한다. 실제 탑승 애니메이션은 별도 범위다.
- 안전한 바깥 차로 진입이 불가능할 때 강제로 조향하지 않는다. 대기·미서비스 기록
  정책을 정하고, 미션 정지 사유와 Autoware 정지 사유를 분리한다.
- ROS 연결·위치 정보가 끊기면 UI에 실패 상태를 표시하고 출발 명령을 내지 않는다.

## 구성과 연결 지점

1. **버스 차량 프로필**: CARLA `vehicle.mitsubishi.fusorosa`를 사용한다.
   공식 [0.9.16 차량 목록](https://carla.readthedocs.io/en/0.9.16/catalogue_vehicles/)
   및 로컬 설치의 FusoRosa 에셋을 확인하고, 실제 생성·물리 값을 기록했다.
   보고된 bounding box는 약 10.27 × 3.94 × 4.25m다. 정류장 차로 폭 3.5m보다
   넓으므로 물리 충돌 범위까지 포함한 보수적 프로필로 주행을 검증했다.
   정류장별 접근·정렬과 차체 전체의 경계 내 수용은 별도 검증이 남아 있다.
   공식 목록상 문 열림 기능은 없으므로 승하차 상태는 UI로 표현한다.
2. **노선·정류장 설정**: 지도 좌표계, 순서, 진행 거리, 차로 ID, 정차 기준 위치를
   저장했다. 승객 대기 영역과 서비스 접근 구간은 후속 작업이다.
   CARLA 좌표와 ROS map 좌표를 구분한다.
3. **미션 관리자 요구사항**: 현재 노선 진행률과 다음 정류장, 하차벨, 승객 상태를 통합해
   서비스 정차 여부와 완료를 결정한다. 이벤트와 시뮬레이션 시각을 기록한다.
4. **Autoware 연결**: 차선 변경·경로·감속·재출발은 Autoware 계획과 제어를 거친다.
   CARLA autopilot이나 직접 조향·브레이크로 버스 미션 주행을 대신하지 않는다.
5. **서비스 UI 요구사항**: 현재/다음 정류장, 노선 진행률, 속도, 하차벨 접수, 대기 승객 수,
   정차 이유, 남은 승하차 시간, 연결 상태를 표시한다. 정류장별 승객 배치 등
   실험 조작과 승객용 하차벨을 구분한다. 기존 정지 버스·정류장 확인 UI는
   카메라 미리보기용이며 이 서비스 UI가 아니다. 별도 `run_bus_service` UI에는
   다음 정류장·속도·하차벨 상태·대기시간·연결 상태를 구현했고, 승객 수는 아직 연결하지 않았다.

기존 Prius 설정은 유지하고, 버스 전용 설정은
`config/carla/vehicle_profiles/fusorosa/`에 분리했다. 실제 측정한 축간거리·외곽 크기·
조향 한계, 지붕 위 센서 위치, 페달 측정 기반 가감속 표를 사용한다.
브리지는 생성된 차량 형상과 설정이 다르면 시작을 거부한다.
`./scripts/carla/build_bus_image`로 전용 이미지를 만들고
`./scripts/carla/carla_autoware start-bus`로 실행한다. 전체 계획 상한은 50km/h이며
지도상의 도심 30km/h 제한을 함께 적용한다. 자동으로 Engage하지 않는다.
RViz는 보수적 차량 외곽 상자를 표시한다.

### 기본 제어 검증 이력 — 2026-10-22

2026-10-22 경로 거부 원인과 기본 주행 문제를 수정했다. 몸통 폭은 약 3.18m지만
앞바퀴 물리 충돌 범위는 약 3.896m다. 차량 외곽을 축소하지 않고 mesh bbox와
바퀴 충돌구를 포함하는 **폭 약 4.040m**의 보수적 프로필을 사용한다.
버스 전용 옵션에서만 차선 변경이 허용된 동일 방향 이웃 차로까지 목적지 외곽을
검사하며, 도로 밖·실선·반대 차로로 검사 영역을 임의 확장하지 않는다.
원본 OpenDRIVE로 확인한 차선 변경 태그는 별도 `Town05Bus` 지도에 복원했다.

페달 표의 엄격한 단조 조건과 목표 정지 상태 전환을 수정한 뒤, 빈 도로의 Autoware
직진·곡선·목표 정지 시험을 통과했다. 직진 약 59m, 곡선 약 177m/88도,
목표 정지 오차 약 0.75m/0.73m, 3초 정지 유지, 충돌 0건이다.
이 결과는 순환로의 제한된 기본 시험이며 전체 노선·교차로·주변 차량 대응의 증거는 아니다.
[10km/h 시험 결과](validation/carla-bus-envelope-20261022/README.md)를 따른다.
이후 당시 운행 상한을 20km/h로 높여 약 478m 주행·목표 정지까지 확인했다.
[당시 20km/h 속도 검증](validation/carla-bus-speed-20261022/README.md)에 기록한다.
후속 30/50km/h 설정과 전체 노선 검증은 [실행·검증 안내](carla-bus-operations.md)를 따른다.

### 노선 주행과 서비스 정차 연결

`set_route`는 현재 VTD 지도·환경을 전제로 하므로 그대로 버스 노선 설정기로 쓰지 않는다.
CARLA 전용 `./scripts/carla/run_bus_lap`은 경로 제출·경유점 추적·S01 복귀를 수행한다.
S08 통과 후 복귀 경로를 주행 중 갱신하며, 기본 시험은 서비스 정차 없이 진행한다.
모든 정류장을 개별 최종 목적지로 제출하면 빈 정류장에서도 목적지 정지가 발생할 수
있으므로, 노선 유지와 조건부 서비스 정지를 분리한다. `--stop-at-all-stops`는
개별 정지 목표 시험 옵션이며 하차벨·승객 조건을 구현한 기능이 아니다.

정차점 삽입/해제는 설치된 Autoware의 지원 인터페이스와 속도 계획 모듈을 먼저
확인하여 선택한다. 외부 속도 제한만으로 정확한 정차 위치·재출발까지 해결됐다고
가정하지 않는다. 정류장 쪽 차로 진입도 임의의 전역 x/y 비교 대신 지도 방향을 사용한다.

다음 작업은 S10 시범 동작을 노선의 다음 정류장 선택과 연결하고, 단계 2의 바깥 차로
접근·경계 문제를 정류장별로 검증하는 것이다. 최초 S02 서비스 목표는 차체 경계 검사에서
거부됐으며 검사를 완화하지 않았다. 이후 승객 조건, 반복 순환 순으로 연결한다.
일시적 긴급 상태와 커브 전후 과도한 감속도 개선 대상으로 유지한다.

서비스 결과는 [2026-10-26 하차벨 검증](validation/carla-bus-service-20261026/README.md),
전체 코스 결과는 [2026-10-24 최종 교통 시험](validation/carla-bus-lap-20261024/following-validation.json)의
`final_traffic_lap`을 기준으로 한다. 초기 기본 제어 실패·수정 기록과
[2026-10-22 저속 완주](validation/carla-bus-lap-20261022/README.md)는 당시 조건의 이력으로 보존한다.

## 발표용 평가 기준

같은 노선에서 정류장마다 하차벨/승객 조건을 바꿔 한 화면에서 판단 근거와 동작을
보여준다. 각 조합은 최소 3회 반복하고 실패도 보존한다.

- 요청 정류장 정차 성공률, 빈 정류장 서비스 통과 성공률.
- 정차 기준 위치 대비 종·횡 오차, 실제 속도, 정지 유지 시간, 재출발 시간.
- 하차벨 입력부터 UI 접수·미션 상태 반영까지 지연.
- 차체 기준 차로 이탈, 충돌, 급제동, 안전 개입 건수.
- 정상 배속 궤적 발행 주기와 계획 처리 시간. 저배속 성공은 별도로 보고한다.
- GT를 사용한 판단·계획 검증인지 센서 검출까지 포함한 결과인지 명시한다.

S10 시범 시험은 목표 대비 종방향 1.5m 미만·횡방향 0.65m 미만·속도 0.05m/s 미만을
연속 5초 만족해야 통과한다. 다른 정류장의 허용 오차와 승차감 가감속 상한은 후속 검증한다.
센서 기반 승객 인식은 GT 미션 완성 후 확장 단계로 분리한다.
