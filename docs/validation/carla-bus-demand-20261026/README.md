## 전체 코스 재검증

```bash
./scripts/carla/run_bus_service log/bus-demand-20261026/mixed-26027-06 \
  --demand-service --laps 2 --random-bell-seed 26027 --auto-start
```

첫 바퀴 승객 배치는 S03 1명, S06 1명, S09 1명, S01 2명이다. 시드에 따른
첫 바퀴에서는 아래 네 가지 조합을 모두 실제 주행으로 확인했다.

- 승객만: S09, S01
- 승객+벨: S03, S06
- 벨만: S04, S05, S08, S10
- 모두 없음: S02, S07

두 번째 바퀴에는 승차한 사람을 재생성하지 않고, 첫 바퀴에 통과한 S02·S07도
하차벨로 정차하도록 계획했다. 06 실행은 두 번째 바퀴 S07 접근에서 중단됐으므로
완료로 간주하지 않는다. 정상 유한 시험은 S01을 12m 지난 별도 종료점에서 정차한다.
자동 시험 중에는 수동 버튼과 Space 입력을 잠근다.

`waiting-passenger.png`는 초기 시험에서 실제 생성된 S03 보행자, `bell-target-ui.png`는 실제
주행 중 S04 하차벨 접수 화면이다. 승차 애니메이션 없이 5초 서비스 완료 후
해당 정류장의 소유 액터를 제거한다. 최종 목표는 S04/S05/S07/S08의 시설 기준점과 나머지 정류장의 시설 6m 전 위치다.
버스 문 위치와 승객의 보행을 맞추는 세부 연출은 별도 개선 대상이다.

## 종료 경계 보완과 검증 범위

`tail-regression-02`에서 S06·S08·S09 무요청 통과와 S07·S10·S01 벨 서비스,
각 재출발까지 확인했다. 그러나 마지막 S01 이후 종료 목표가 다음 바퀴 S10으로
바뀌는 오류로 종료에 실패했다. 경로 재변경도 늦어졌고 이후 코스 기준 이탈로 중단됐다.
이 실행도 성공으로 집계하지 않는다. 종료 시 설정은 30m·후진 허용 두 옵션으로 복원됐다.

유한 시험의 마지막 S08 이후에는 남은 서비스 목표를 우선 처리한 다음 종료 목표를
유지하도록 수정했다. 현재 목표뿐 아니라 새 목표까지 남은 거리도 경로 변경 기한에
반영한다. 무한 운행은 기존 순환 목표를 유지하며 순수 정책 테스트에서 구분해 확인한다.
`terminal-regression.py`는 S10→S01 서비스→종료만 재현하므로 전체 완주로 집계하지 않는다.

수동 벨 중복 입력은 `manual-bell-command-check.json`의 격리된 명령 처리 검사로 확인했다.
`post-run-manual-bell.patch`는 해당 수정 당시의 부분 차이이며 최종 전체 변경본은 아니다.
`bus-demand-S09-boarding.png`는 실제 승객만 대기하던 S09에 버스가 정차한 화면이다.
당시 UI 하단에 이전 정류장 이름이 남던 표시도 수정했다.

`terminal-regression-01`은 최종 코드로 96.07m 구간을 통과했다. S01 벨 정차 5.05초,
재출발 5.23m 확인 후 종료점에 정상 정지했다. 충돌·신호 위반·긴급 상태 진입은 0건,
정지선 녹색 통과 1회이며 원래 운행 설정의 복원도 확인했다. 원본의 `completed_laps`는
0으로 기록하고, 재현에 사용한 논리 바퀴 번호는 별도 필드로 보존한다.

최종 검사는 버스 정책/신호/추종 테스트 46개와 원본 지도 경계 테스트 4개 통과,
Python 구문·셸 구문·diff 공백·문서 링크 확인이다. 수정 후 전체 두 바퀴 연속 운행과
교통 차량 동시 조건은 아직 재검증하지 않았다.

최종 수동 화면은 출발 대기로 유지했다. `manual-ready-actors.json`에서 S03 2명,
S06 1명, S09 2명을 확인했고, `manual-ready-S03.png`와 `manual-ready-ui.png`로
실제 사람 표시와 전체 대기 5명 UI를 확인했다. S01·다음 S02에는 승객이 없다.
