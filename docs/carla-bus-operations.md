# 버스 실행·검증·백업 안내

문서 정리: 2026-10-26. 최신 주행 검증: 2026-10-24.

2026-10-24 최종 강화 시험은 차량 16대를 처음부터 끝까지 유지하며 **2,005.33m를 완주**했다.
버스·NPC 충돌 감지, 차량 소실, 비정상 제어값은 모두 0건이었다. 최소 관측 차체 간격은
1.282m, 신호 통과는 녹색 13회·황색 1회, 실제 최고 속도는 도심 26.84km/h·순환로
46.49km/h였다. 일시적 긴급 상태 2회는 자동 회복했다. 이동 중 최신 경계 표본 649개는
모두 유효한 다각형이었으나, 순간 경계 밖 차체 면적이 0.1m²를 넘은 표본 5개는 남았다.
아래 초기 완주·실패 기록은 별도 조건의 이력이며, 최종 판정은
[후행 차량 검증 기록의 final_traffic_lap](validation/carla-bus-lap-20261024/following-validation.json)을 따른다.
이 시험은 GT 객체·신호 입력과 NPC 추종 보완을 적용한 한 바퀴 정류장 경유 시험으로,
하차벨·승객·정류장 서비스 정차와
보행자 대응의 검증은 아니다.

현재 운행 상한은 도심 30km/h·순환로 50km/h다. 아래 기본 제어 검증 도구의
20km/h 기본값 및 과거 10/20km/h 시험 결과와 구분한다.
전체 구현 단계와 다음 작업은 [미션 설계](carla-bus-mission.md#구현-및-검증-순서)를 따른다.

## 현재 PC

CARLA 0.9.16, Docker/NVIDIA 실행 환경, 기존 Autoware 이미지, Town05 지도와 ML 모델이
설치된 `/home/a/carla_pp` 환경을 기준으로 한다. 두 터미널에서 실행한다.

```bash
# 터미널 1: 서버가 실행 중이면 중복 실행하지 않는다.
./scripts/carla/carla_run -quality-level=Low
```

```bash
# 터미널 2: 다른 차량 실행을 종료하고 버스 실행
./scripts/carla/carla_autoware stop
./scripts/carla/build_bus_image
./scripts/carla/carla_autoware start-bus
```

`start-bus`는 Fuso Rosa 한 대, GT 물체 입력, direct localization, 50km/h 계획 상한,
신호 브리지와 버스 추적 카메라로 시작한다. 자동으로 Engage하지 않는다.
`prepare_bus_map`을 호출해 원본 Town05를 보존한 별도 Town05Bus 지도를 사용한다.
첫 생성/지도 업그레이드는 Autoware를 정지한 상태에서 한다.
기존 Prius는 `start-town05`와 기존 이미지/지도를 계속 사용한다.
버스 지도는 도심 30km/h, 서부 순환로(native road 36/37) 50km/h다.
이는 상한이며 신호·곡률·주행 가능 영역 검사로 실제 속도는 낮아질 수 있다.

`start-bus`는 S01~S10의 오른쪽 인도에 `static.prop.busstop` 정류장 시설도 배치한다.
지붕·벤치·측면 안내판이 있는 모델을 도로와 나란히, 입구가 도로를 향하도록 놓는다.
시설은 해당 CARLA 월드가 유지되는 동안 남으며, 월드를 다시 불러온 뒤에는 재배치한다.
버스를 정지한 상태에서 시설만 배치하거나 복원하려면:

```bash
./scripts/carla/place_bus_stops
./scripts/carla/place_bus_stops --dry-run # 배치 예정 좌표만 확인
```

정류장별 role_name으로 기존 시설을 재사용한다. 3번은 가로등을 피하도록 진행 방향의
뒤쪽으로 4m, 9번은 뒤쪽 생울타리와 간격을 두도록 인도 안에서 도로 쪽으로 0.4m 조정했다.
이 보정은 시설 위치에만 적용하며 도로상의 정차 기준점은 유지한다.
10곳의 실물 배치와 재실행 시 중복 없음은 확인했으며, 시설 설치가 하차벨·서비스 정차
기능을 구현하는 것은 아니다.

별도로 임시 정류장 번호와 참조 노선을 CARLA에 표시하려면:

```bash
/home/a/CARLA/venv-0.9.16/bin/python tools/carla_bus_route_preview.py --duration 3600
```

기존 정지 버스 확인 UI는 [노선 안내](../scenarios/bus/README.md)를 따른다.
하차벨 기능이 구현된 승객용 UI와는 다르다.

## 직선 중앙 주행 개선 및 구간 검증 — 2026-10-23

직선에서 차선 중앙 경로를 유지할 수 있도록, Town05 경계 174곳(도로 가장자리
87곳, 도색 중앙선 87곳)에 실제 평평한 포장면을 확인한 여유 폭을 기록했다.
차선 좌표·폭·중앙 경로와 차선 변경 허용 태그는 바꾸지 않는다.
`config/carla/bus/town05_straight_margins.json`의 v2 측정은 CARLA 메쉬의
Roads/RoadLines 표면과 높이 및 동일 도로 내 전후 최대 8m의 직선 조건을 확인한다.
바깥 경계는 네이티브 Shoulder 안에서 최대 0.65m(도심은 보통 0.45m),
도색 중앙선은 양 방향의 포장면을 확인한 경우 차체 여유만 최대 0.5m 허용한다.
이는 반대 차로로 경로를 생성하거나 중앙선 횡단을 허용하는 설정이 아니다.
연석·보도·물리 중앙분리대와 검증되지 않은 구간은 확장하지 않는다.
BPP의 파란 경계와 버스 목적지 차체 검사는 같은 검증 메타데이터를 사용한다.
폭은 경계 끝에서 점진적으로 줄이며, BPP의 장애물 검사와 MPT의 전체 차체 검사를 유지한다.
순환로 두 커브의 경계 정점 1,241개를 확인했으며 확장 폭은 모두 0이었다.
MPT에는 `straight_reference_weight: 10.0`을 적용해 반복 최적화 중에도 최초
입력 경로를 직선의 중심 기준으로 유지한다. 차체 길이 주변의 곡률에 따라 보정을
줄이고, 곡률 0.007/m 이상인 커브에서는 이 추가 가중치가 0이 된다.
`prepare_bus_map`은 원래 지도 좌표와 일치하는 경우에만 이 메타데이터를 설치한다.
v2 도심 road 44 검증에서는 파란 경계의 실제 확장 폭이 중앙선 쪽 0.50m,
바깥쪽 0.45m였다. 시작·목표를 차선 중앙으로 설정한 안쪽/바깥쪽 약 30m
시험은 모두 충돌 없이 목표 정지까지 통과했다.
[경계 확장 검증](validation/carla-bus-lap-20261023/blue-boundaries-results.json)에 기록한다.
아래 비교 수치는 앞서 검증한 v1 경계 설정의 결과이며 v2 재측정값과 구분한다.
짧은 직선의 동일 조건 비교(road 37, s=345~375m, 2m/s 이상 표본)에서 바깥 차선의
계획 편차 중앙값은 0.701→0.045m, 실제 편차는 0.690→0.016m였고,
안쪽 차선 실제 편차는 0.733→0.063m였다. 비교 시험의 시작·정지 목표는 모두
인접 차선 방향으로 0.65m 치우친 동일 위치이며, 출발 정렬과 목표 접근은 비교 구간에서 제외한다.
20km/h 커브 시험 약 177m와 도심 road 44 시험 약 39m도 충돌 없이 완료했다.
긴 직선에 포함된 짧은 커브 전후에는 약 5.5km/h까지 감속하는 구간이 남았으므로
이 결과를 50km/h 순항 또는 전체 코스 재검증 완료로 간주하지 않는다.
[측정 결과](validation/carla-bus-lap-20261023/centering-results.json)와
[계획·실제 궤적 비교](validation/carla-bus-lap-20261023/centering-comparison.png)를 보존한다.

## 기본 AUTO 주행 시험

아래 명령은 실제 버스를 움직인다. Town05에 버스 한 대만 있고 보행자/배경 차량이
없는 상태를 요구한다. STOP 확인 후 시작 위치를 옮기고, ADAPI 경로 제출과 AUTO로
주행한다. CARLA autopilot이나 직접 페달 명령으로 시험 주행을 대체하지 않는다.

```bash
./scripts/carla/validate_bus_control straight
./scripts/carla/validate_bus_control curve
./scripts/carla/validate_bus_control speed # 기본 20km/h, 곡선 포함 약 478m
# 결과 폴더를 직접 정할 수도 있다.
./scripts/carla/validate_bus_control straight /tmp/bus-straight 20
./scripts/carla/validate_bus_control speed /tmp/bus-ring50 50
```

직진은 road 37/lane -2의 s=330→390, 곡선은 s=130→300, 긴 속도 시험은
s=20→490을 사용한다. 기본 속도는 20km/h이고 세 번째 인자로 50km/h 이하의 상한을
지정할 수 있다. `speed` 시험은 상한의 95% 이상을 연속 5초 유지해야 통과한다.
검증 도구는 50km/h 초과 입력을 거부한다.
목표 오차 1.5m 미만, 속도 0.05m/s 미만 5초 유지, 최고 속도 2m/s 초과,
중심선 거리 1m 이하와 충돌 없음이 통과 조건이다. 중심선 거리는 rear axle의
3차원 위치 차이이므로 도로 높이 오차도 포함한다. 결과 JSON/로그는 기본적으로
`log/bus-control-날짜시각/`에 저장하며, 성공/실패 후 STOP과 경로 해제를 확인한다.

## 정류장 노선 한 바퀴 시험

```bash
./scripts/carla/run_bus_lap
# 선택: 실패 구간 진단. 전체 완주 결과로 처리하지 않는다.
./scripts/carla/run_bus_lap /tmp/bus-suffix --start-anchor S04
# 특정 구간만 진단. 중간 목표에서 정지하며 전체 완주로 기록하지 않는다.
./scripts/carla/run_bus_lap /tmp/bus-section --start-anchor S04 --end-anchor S05
# 배경 승용차: 코스 기준 초기 동일 방향 8대 + 반대 방향 8대
./scripts/carla/run_bus_lap /tmp/bus-traffic --with-traffic
# 문제 분리: 맞은편 또는 후행 차량 한 대, S01→S03 구간만
./scripts/carla/run_bus_lap /tmp/bus-opposing --with-traffic --traffic-layout opposing --end-anchor S03
./scripts/carla/run_bus_lap /tmp/bus-following --with-traffic --traffic-layout following --end-anchor S03
```

S01에 최초 배치한 뒤 S10 방향 경로로 출발한다. 같은 시작 lanelet을 한 경로에
중복할 수 없는 제약 때문에 S08 통과 후 남은 경유점을 포함한 S01 복귀 경로로
주행 중 갱신한다. Autoware의 재경로 안전 검사를 유지하며, 경로 전환을 위한
S10 정차는 요구하지 않는다. 복귀 경로를 승인받지 못하면 성공으로 처리하지 않는다.
정류장과 순환로 경유점의 순서, 충돌 없음, 입력 최신성, 목표 오차 1.5m 미만과
정지 유지 5초를 확인한다. 무진행 120초·충돌·입력 단절 시 중단하고 STOP 처리한다.
정류장 바깥 차로를 우선 경로로 지정하고 실제 통과 차로를 별도로 기록한다.
단, 해당 차로에서 다음 경로 구간으로 직접 연결되지 않으면 원래 교차로 진출
차로를 유지한다. S07에서 바깥 차로를 영구 우선으로 고정하면 좌회전 연결을
잃고 차로 끝에서 멈추는 문제가 있었다. 이번 무정차 시험의 진출 차로 유지와,
정류장에 접근·정차한 뒤 진출 차로로 복귀하는 서비스 운행은 구분한다.
서비스 정차와 모든 정류장의 정확한 바깥 차로 정렬은 별도 검증 대상이다.
`--stop-at-all-stops`는 각 정류장을 개별 정지 목표로 사용하는 별도 시험이며 하차벨 기능은 아니다.
기본 전체 상한은 50km/h이고 지도상의 도심 30km/h 제한을 함께 적용한다.
실제 속도는 곡선·신호·계획 결과에 따라 낮아진다.
순환로 road 37에서는 진입 후 가운데 차로에서 안정된 것을 확인하고 첫 직선
`s=25~100m` 안에서 바깥 3차로를 요청한다. `s=130m` 전에 정렬하지 못하면
진단을 중단한다. 두 큰 커브는 바깥 차로로 유지하고 마지막 커브 뒤
`s=670m`부터 가운데 차로, 정렬 확인 후 1차로를 순차 요청한다.
`s=785m`까지 복귀하지 못하면 중단한다. 변경 구간 상한은 20km/h,
순환 주행 상한은 50km/h다. 이는 경로 요청 정책이며 실제 성공 여부는 주행 로그로 확인한다.
형광색 선도 직선 구간에서 차로를 전환하도록 생성하지만 제어 궤적은 아니다.

버스의 전체 충돌 크기와 도로 경계 검사를 유지하면서 MPT의 추가 경계 여유만
직선 0.1m, 커브 0.3m로 설정한다. 차량 길이만큼 전후 곡률을 함께 보고 연속적으로
전환한다. 차선 변경의 원시 중심선 착지 경계 필터는 버스 프로필에서 해제하고,
최종 궤적의 실제 도로 경계 검사와 장애물 검사는 유지한다. 이 설정의 실제
바깥 차로 주행 최고 속도는 48.41km/h였고, 출구 직선 복귀와 S06 도착 구간은
483.78m, 충돌 0건으로 통과했다. 이후 직선 경계 v2의 전체 코스에서는
2,006.91m를 충돌 없이 완주했다. S01→S10→S01 복귀와 목표 정지를 확인했고,
기록된 정지선 통과 14건은 모두 녹색이었다. 실제 최고 속도는 도심 26.40km/h,
순환로 46.41km/h였다. 일시적 경로 변화 진단과 짧은 커브 전후 감속은 남는다.
[전체 주행 결과](validation/carla-bus-lap-20261023/blue-boundaries-full-lap.json)에
상세 기록과 미검증 항목을 보존한다.
뒤쪽 경로 연결부가 차량 근처에서 인위적인 곡률을 만들지 않도록 BPP 후방 길이
25m, path smoother/MPT 후방 길이 20m를 함께 적용한다. MPT는 90개 점을 사용해
전방 계획 거리도 유지한다. 변경 전후의 직선 바깥 차로 중심 오차 중앙값은
약 0.70m → 0.50m였다. 차량 폭과 지도 차선 폭은 바꾸지 않았다.
`signal_crossings`에는 전면 중앙이 정지선을 통과한 시점의 실제 CARLA 신호를 기록한다.
연속 두 표본에서 적색/알 수 없음인 통과는 중단하며, 표본 사이 신호 전환은 별도 검토한다.
이 기록만으로 모든 교통 규칙이나 차체 전체의 정지선 준수를 형식 검증했다고 보지는 않는다.

## 교통 시험 조건과 수정 이력 — 2026-10-23~24

이 수치는 주행 가능 영역의 모든 형태 문제가 해결되었다는 뜻이 아님을 보여준다.

저속 차선 변경의 과도한 감속은 공간 길이를 확보하려고 낮춘 횡가속도 맵이
곡률 기반 속도 제한에도 적용된 결과였다. 버스 일반 차선 변경에 별도의
`lane_change.trajectory.minimum_lane_change_length: 30.0`을 사용하고,
횡가속도 상한을 0.693m/s², 횡가속도 변화율을 0.4m/s³로 유지한다.
기본 최소 길이는 0이므로 다른 프로필은 기존 동작을 유지한다. 공간이 부족하면
일반 후보를 억지로 짧게 만들지 않으며, 기존 저속 복구 경로는 별도의 물리·충돌
검사를 유지한다. 공유 매개변수 구조 변경에 맞춰 일반·회피·외부 요청 차선 변경
플러그인을 함께 빌드한다.
길이 분리 후 S03→S05 교통 시험은 255.66m를 접촉 없이 통과했고, S03 road 5에서
이동 중 속도 중앙값은 이전 2.64km/h 대비 5.23km/h였다. 두 시험의 신호·교통
상황은 동일하지 않으므로 전체 소요 시간만으로 성능 향상을 단정하지 않는다.

추가 경계 여유 요청은 `dynamic_expansion.ego.extra_width`를 1.0m에서 1.4m로
늘려 반영한다. 이는 여유 있는 영역에서 목표 폭을 총 0.4m 늘리는 설정으로,
모든 경계를 일괄 0.2m씩 옮기는 설정이 아니다. 검증된 도로 끝 여유, 중앙 경계,
물체 배제와 최대 확장 제한은 유지한다. 버스·차선·지도 좌표는 바꾸지 않는다.


경계 1.4m와 길이 분리를 함께 적용한 첫 전체 시험은 S07 이후 적색 정지선 통과로
중단했다. 버스·NPC 접촉은 모두 0건이었고, 황색 통과 허용 로그가 3초 연속
기록됐다. 기존 황색 판단은 매 갱신마다 전체 황색 시간을 다시 사용하고,
물리 정지선보다 5m 앞의 정지 목표점을 도달 거리로 사용했다. 일반·실험 신호
모듈 모두 마지막으로 확인한 녹색 관측 시각에서 남은 황색 시간을 보수적으로
계산하고, 실제 정지선까지의 거리로 도달 가능성을 판단하도록 수정했다.
처음부터 황색만 관측했거나 정보가 오래됐을 때는 전체 남은 시간을 가정하지 않는다.
황색 후반 갱신·5m 정지 여유·처음 관측한 황색을 포함한 신호 테스트 35개가 통과했다.
실제 주행 재검증 결과는 위 후행 차량 검증 기록의 `yellow_phase_fix`와
`final_traffic_lap` 항목을 따른다.


황색 수정 후 첫 완주는 2,005.63m, 접촉 0건, 녹색 통과 14건이었다. 그러나
후속 로그 점검에서 인접 차량 1대가 사라진 뒤 버스가 재출발한 것을 확인했으므로
이를 16대 유지 검증으로 인정하지 않는다. 약간 비스듬한 옆 차량 좌표계에 긴
버스 전체를 투영하면 후행 차량으로 잘못 분류하는 경우를 수정했다. 후행 보완은
차와 버스 양쪽 횡방향 축에서 차체 영역이 겹칠 때만 적용한다.
CARLA 0.9.16의 목표 속도 분모가 0이 되는 계산을 피하도록 NPC 추종 목표의 하한은
0.01km/h로 설정한다. 정확한 정지 명령이 아닌 거의 0에 가까운 목표이며, 6m 간격과
기본 Traffic Manager의 충돌·신호 제동은 유지한다. 이 원인은
[CARLA MotionPlanStage](https://raw.githubusercontent.com/carla-simulator/carla/0.9.16/LibCarla/source/carla/trafficmanager/MotionPlanStage.cpp)의
`velocity_deviation` 계산과 실제 NaN 제동 기록을 대조했다.
시험 중 NPC 소실 또는 NaN/무한 제어값이 관측되면 즉시 실패 처리한다.


강화 검사 첫 시험은 S03 뒤 154.66m에서 경계 정지 후 뒤차가 소실되어 실패했다.
현재 차체는 경계 안이지만, 도로 가장자리와 내부 차선 사이의 연결점이 좁게
남아 다음 궤적을 막았다. 확장 폭 할당이 양 끝점 제한의 최솟값을 사용해,
도로 끝의 고정 조건을 내부 점에도 강제로 적용하는 문제였다. 각 점의 실제
도로·물체 제한을 따로 적용하고, 여러 경로 표본이 공유하는 점에는 필요한
확장 폭 중 최댓값을 유지하도록 수정했다. 최종 경계 평활화 뒤에도 모든 제한을
다시 적용한다. 관련 회귀 2개를 포함한 경계 테스트 23개가 통과했다.
