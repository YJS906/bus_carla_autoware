# 승객·하차벨 기반 정류장 서비스


## 승객과 하차벨을 함께 사용하는 전체 코스 모드

`--demand-service`는 S01부터 전체 노선을 순환하며 10개 정류장 각각의 승차 대기 인원과
하차 요청을 확인한다. 기존 UI에 다음 정류장의 대기 인원, 누적 승차 인원, 정차 이유를
표시한다. 하차 요청은 대상 정류장 이름과 함께 빨간색으로 깜빡인다.

| 대기 승객 | 하차벨 | 동작 |
| --- | --- | --- |
| 없음 | 없음 | 정류장 주변 10km/h 이하로 서행 통과 |
| 있음 | 없음 | 정차 → 5초 승차 대기 → 출발 |
| 없음 | 있음 | 정차 → 5초 하차 대기 → 출발 |
| 있음 | 있음 | 정차 → 5초 승하차 대기 → 출발 |

서행 통과에서도 신호·장애물에 따른 정지는 유지한다. 정류장의 지정 위치·차로에서
실제 정지를 확인해야 승하차 대기로 인정하므로 신호 대기로 하차 요청이 지워지지 않는다.
접수 거리가 부족한 늦은 하차벨은 다음 도달 가능한 정류장으로 이월하고 UI에 대상 정류장을 표시한다.

```bash
# S03 2명, S06 1명, S09 2명 배치. 출발 버튼과 Space로 조작
./scripts/carla/run_bus_service /tmp/bus-demand --demand-service
# 정류장별 승객 수 직접 지정. 생략한 정류장은 0명, 각 정류장 0~3명
./scripts/carla/run_bus_service /tmp/bus-demand-custom --demand-service --passenger-stops S02:1,S03:2,S06:1
# 네 가지 조합을 포함하는 무개입 시험: 승객 배치와 하차벨 시점을 시드로 재현
./scripts/carla/run_bus_service /tmp/bus-demand-random --demand-service --laps 2 --random-bell-seed 26027 --auto-start
```

승객은 정류장 쉼터 옆의 실제 인도 위에 CARLA 보행자 액터로 배치한다. 이 단계의
승객 판단은 지정 구역에 생성한 액터의 상태를 읽는 GT 방식이며 카메라 인식이 아니다.
차도로 걷지 않으며, 승차 완료 시 해당 액터를 제거하고 누적 승차 수를 올린다.
문 개폐·탑승 보행 애니메이션은 포함하지 않는다. 다음 바퀴에 승객을 자동 재생성하지 않는다.
기본 배치는 S03 2명·S06 1명·S09 2명이고 출발점 S01에는 없다. 출발 대기 중에도
승객이 표시된다. 종료 시 이번 실행이 생성한 승객만 정리한다. 기존 배경 차량·보행자가 있으면 시작을 거부한다.

정차 목표는 `scenarios/bus/town05_bus_service_stops.json`으로 시설 기준점과 구분한다.
기본 목표는 시설 기준 6m 전의 rear axle/base_link 위치이고, 차로 중심에서 안쪽으로
0.45m 보정한다. 짧은 교차로 진입부가 있는 S04·S05·S07·S08은 시설 기준점을 사용한다.
승차 처리는 지정 정류장 단위의 시뮬레이션이며 실제 문 위치 보정·탑승 보행은 포함하지 않는다.

수요 기반 모드가 활성화된 동안 차로 변경의 추가 최소 길이 설정을 30m에서 16m로
조정한다. 속도에 따른 횡가속도·jerk 길이 계산, 차체·충돌·곡률 검사는 그대로 유지하며
횡가속도와 jerk 검사가 켜져 있지 않으면 출발을 거부한다. 긴 최소 길이 때문에 정차
진입과 출발을 모두 확보할 수 없던 S07을 위한 정류장 운행 설정이다. 기존 S10 전용
모드와 기본 버스 프로필은 바꾸지 않는다. 종료 시 STOP/경로 정리 뒤 이전 값을 복원하고
실제 복원 결과를 기록한다. 출발 계획의 후진 옵션 두 개도 세션 동안 끄며, 실제
종방향 속도가 -0.2m/s 미만이면 즉시 중단한다. 후진 옵션도 종료 시 이전 값으로 복원한다.
정류장 접근·통과 상한은 10km/h다. 무요청 중간 정류장에는 불필요한 바깥 차로 접근을
강제하지 않는다. R06은 검증된 바깥 접근을 유지하고, 무요청 S06에서는 미리 출구 차로를 선택한다.

기존 5초 정차·재출발 확인·충돌·신호·속도 감시를 그대로 적용한다.
S02의 목표 차체 검사를 위해 원본 OpenDRIVE에서 변경 허용을 확인한 road 8 공유 경계
태그를 복원했다. [지도 근거](../maps/Town05Bus/README.md)를 참고한다.

무작위 시험은 첫 바퀴에 네 조합을 모두 배치하고 두 바퀴 동안 각 정류장의 서비스 정차를
최소 한 번 시험하도록 구성한다. 시험 중 버튼/Space 입력은 잠그고 모든 입력 시점과
승객·서비스·통과·재출발 이벤트를 결과에 기록한다. 유한 바퀴 시험의 마지막 정지는
S01을 12m 지난 검증 종료점이며 승하차 요청 때문이 아니다.

아래 단일 정류장 및 S10 연속 순환 설명은 기존 모드에 해당한다.

## 기존 단일 정류장 시범

2026-10-26. 첫 서비스 구간은 **S09 출발 → S10 선택 정차 → S01 시험 종료**다.
하차벨이 접수되면 S10 바깥 차로의 목표 위치에 정차하고, 실제 정지를 확인한 뒤
시뮬레이션 시간 5초 동안 대기한다. 서비스 완료 시 요청을 해제하고 S01로 재출발한다.
벨이 없으면 S10에 서비스 정지 목표를 만들지 않고 통과한다. 신호·장애물 정지는 유지한다.

이 기존 모드는 승객 판단을 사용하지 않는다. **S01은 이 시험을 마치는 목적지이므로
벨이 없어도 마지막에 정지한다.** 기본 명령은 짧은 시범 구간이다.
기존 `run_bus_lap`의 전체 코스 시험과 구분한다.

## 전체 코스 연속 순환

`--continuous`는 S01에서 출발해 전체 노선을 반복한다. 서비스 대상은 아직 **S10 한 곳**이다.
S10 요청이 없으면 통과하고, 요청이 있으면 위 정차·5초 대기·재출발 절차를 수행한다.
S01은 다음 바퀴로 이어지는 경유점이다. UI에 현재/다음 정류장, 바퀴 수와 정차 이유를 표시한다.
신호 정보가 최신이고 앞쪽 정지 요인이 확인된 경우에만 `신호 대기`라고 표시한다.

```bash
# 사용자 조작: 출발 버튼, 하차벨 버튼 또는 Space
./scripts/carla/run_bus_service /tmp/bus-loop --continuous
# 무개입 검증: 2바퀴, 무요청 통과와 무작위 시점의 벨 요청을 함께 시험
./scripts/carla/run_bus_service /tmp/bus-loop-random --continuous --laps 2 --random-bell-seed 26026 --auto-start
```

무작위 시험은 시드와 입력 시점을 기록하고, 버튼·Space 입력을 잠근다. 전체 시험에
요청/무요청을 최소 한 번씩 임의 순서로 배치하며, 요청 위치는 접수 마감보다 여유 있게 선택한다.
일반 운행에서는 수동 입력이 정상 작동한다. 늦은 입력 자동 이월은 아직 지원하지 않는다.

기본 `--laps 0`은 바퀴 수로 종료하지 않으며, 실행 시간 감시 한도는 5,400초다.
`--laps N` 검증은 N바퀴 뒤 **S01을 12m 지난 별도 시험 종료점**에서 정지한다.
이 마지막 정지는 하차 요청과 관계없는 검증 종료다. 창 닫기/중단 시에도 STOP과 경로 정리를 수행한다.
속도 상한은 도심 30km/h·순환로 50km/h이며, S10 서비스 접근 160m 이내는 20km/h다.

경로는 S10과 다음 바퀴 R02 사이에서 주행 중 갱신해 순환 경계를 이어간다.
다음 바퀴의 S01을 지나면 S10까지 다시 연장한다. 서비스 대상이 아닌 S03은 출구 차로를
미리 선택해 정류장 통과 직후 교차로까지 짧은 구간에서 차로 변경하지 않도록 한다.
Autoware의 경로 변경 가능 상태를 기다리며, 안전하게 이어가지 못하면 실패로 중단한다.
진행률은 현재 위치 주변의 노선 구간에서만 계산해 평행 도로나 순환 경계의 잘못된 점프를 막는다.
`lap_crossings`, `station_passes`, `route_handoffs`, `restart_events`에 바퀴별 결과가 남는다.

빈 도로 두 바퀴 4,021.57m에서 무요청 통과와 무작위 벨 정차·재출발을 완료했다.
[연속 순환 검증과 수정 이력](validation/carla-bus-loop-service-20261026/README.md)을 참고한다.

## 실행

Town05Bus 지도와 Fuso Rosa 전용 Autoware가 실행 중이어야 한다.
빈 도로의 버스 한 대만 허용하며, 배경 차량·보행자가 있으면 시작을 거부한다.
이 실행 도구와 전체 코스·기본 제어 검증은 같은 잠금을 사용해 동시 주행을 막는다.

```bash
# CARLA 서버가 실행 중인 상태에서 버스 실행
./scripts/carla/carla_autoware start-bus

# 하차벨 창 열기
./scripts/carla/run_bus_service
```

창을 열면 STOP을 확인하고 버스를 S09 시작점으로 배치한다. **출발 버튼을 누르기 전에는
주행하지 않는다.** 하차벨 버튼 또는 창에 포커스를 둔 상태의 Space로 요청을 접수한다.
출발 전에 누르거나, 주행 중 접수 가능한 거리에서 누를 수 있다. 반복 입력은 한 요청으로
처리하며, 서비스 완료 전까지 요청을 유지한다. 화면에는 다음 정류장, 속도, 요청 상태,
승하차 대기시간과 오류를 표시한다.
요청이 접수되면 하차벨 버튼에 `하차 요청 접수 · S10`을 표시하고 두 가지 빨간색으로
천천히 깜빡인다(0.5초마다 색 전환). 서비스 완료 후 요청이 해제되면 깜빡임을 멈춘다.

`시험 중단 · 버스 정지` 또는 창 닫기로 시험을 중단한다. STOP을 확인하고 시험 경로와
속도 제한을 정리한다. 완료 창을 닫으면 실행 명령이 종료되며, 새 시험은 명령을 다시 실행한다.
STOP 확인에 실패하면 기존 검증 도구의 시뮬레이터 차량 고정 절차를 적용하고 실패로 기록한다.

한글 글꼴이 없는 컨테이너에는 실행 도구가 호스트의 한글 글꼴 한 개를 복사한다.
자동 선택이 불가능하면 `CARLA_BUS_UI_FONT=/설치된/한글글꼴.ttc`를 지정한다.
글꼴 파일은 저장소에 포함하지 않는다. 새 버스 이미지를 빌드할 필요 없이 실행 시
저장소의 서비스 도구를 컨테이너 `/tmp/bus-tools`로 복사한다.

## 시험 범위와 정차 기준

- 시범 구간 상한은 **20km/h**다. 전체 코스의 도심 30km/h·순환로 50km/h 설정을 바꾸지 않는다.
- 차량 이동은 Autoware의 경로·계획·제어를 사용한다. 시작점 배치 외에 CARLA 위치 이동이나
  직접 페달 제어로 정차·재출발을 대신하지 않는다.
- 정차 목표는 기존 버스 프로필과 동일하게 rear axle/base_link 기준이며,
  차로 중심에서 안쪽으로 0.45m 보정한다. 버스 차체 폭을 축소하지 않는다.
- S10의 road 43/lane -2에서 목표 대비 종방향 오차 1.5m 미만, 횡방향 오차 0.65m 미만,
  실제 속도 0.05m/s 미만을 **연속 5초(시뮬레이션 시간)** 만족해야 서비스 완료로 처리한다.
  이동하거나 허용 위치·차로를 벗어나면 대기시간을 다시 센다.
- 목표 도착 뒤 Autoware가 STOP으로 전환해도 위 정차 조건을 만족하면 대기를 이어간다.
  다른 위치에서 AUTO를 이탈하거나 위치·계획·객체·제어 입력이 오래되면 시험을 중단한다.
- 완료 후 요청을 해제하고 다음 경로를 제출한다. 재출발은 실제 5m 초과 이동과
  0.5m/s 초과 속도로 확인하며, 마지막 S01 목표 정지까지 성공해야 시험을 통과한다.
- 충돌, 적색/미상 정지선 통과, 비정상 제어값, 속도 초과, 장시간 무진행은 실패로 기록한다.

## 늦은 입력과 경로 변경

주행 중 접수 가능 거리는 노선 방향의 남은 거리로 판단한다. 최소 25m와 속도에 따른
계획·제동 여유 중 큰 값을 사용한다. 경로 변경은 Autoware의 재경로 허용·안전 검사를
통과해야 하며, 거리가 충분하다는 이유만으로 강제 승인하지 않는다.

**이번 단일 정류장 버전은 접수 마감 후 입력을 명시적으로 거부한다.** 다음 정류장으로
자동 이월하는 기능은 아직 없다. 이미 접수한 요청의 경로 변경을 제한 거리 전에 완료하지
못하면 요청을 유지한 채 시험을 중단하고 실패로 기록한다. 신호 대기로 요청을 소비하거나
정차하지 않았는데 성공으로 처리하지 않는다.

최초 후보였던 S02는 정지 목표의 차체 경계 검사에서 거부됐다. 경유 성공이 정차 가능성을
보장하지 않음을 확인했으며, 이 검사를 끄거나 지도 폭을 늘리지 않고 기존 정지·재출발
근거가 있는 S10으로 첫 서비스 구간을 정했다. S02와 나머지 정류장의 정차 조건은 별도로 검증한다.

## 재현과 결과

아래 명령은 출발 버튼 없이 실제 시뮬레이션 주행을 시작한다.

```bash
# 출발 전 벨 접수
./scripts/carla/run_bus_service /tmp/bus-service-bell --headless --auto-start --bell
# 주행거리 5m에서 벨 접수
./scripts/carla/run_bus_service /tmp/bus-service-moving-bell --headless --auto-start --bell-after-m 5
# 벨 없이 통과
./scripts/carla/run_bus_service /tmp/bus-service-pass --headless --auto-start
```

결과 폴더에는 `service.json`, `service.log`, 실행 이미지·소스 해시를 담은 `inputs.json`을
저장한다. `service_events`는 서비스 완료, `bell_events`는 접수·중복·늦은 입력,
`signal_crossings`는 신호 통과, `cleanup`은 최종 정지·경로 해제를 기록한다.
`service_completed: false`인 무요청 통과도 정상 시험 결과이며, `success`와 함께 읽는다.
